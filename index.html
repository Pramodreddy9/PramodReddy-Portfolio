CASE STUDY 01 — PLATFORM MIGRATION

Trino → Databricks Migration

Migrated SQL workloads from a Trino-based platform on GCP to Databricks, converting queries to Spark SQL with full functional parity while improving performance, maintainability, and compute cost.

DatabricksdbtAirflowSpark SQLDelta LakePython

Problem & Role

  • Existing Trino workloads on GCP needed to move onto Databricks without breaking downstream consumers or regressing performance.
  • As Data Engineer, I owned the query conversion, pipeline orchestration, and validation of the migrated workloads.

Engineering Work

  • Converted SQL workloads from Trino syntax to Spark SQL, preserving functional parity.
  • Built Airflow DAGs (hourly and daily) with dependency management, retries, and monitoring.
  • Developed modular dbt-on-Databricks models using incremental processing for large-scale transformation.
  • Optimized queries and joins to cut unnecessary data processing and reduce execution time.
  • Applied partitioning, clustering, and Delta optimizations (autoOptimize, autoCompact) to lower Databricks compute cost and avoid full-table scans.
  • Validated and reconciled data across systems, working through Git/GitHub for version control and code review, and partnering with QA to resolve issues end-to-end.
Trino / GCP→ Spark SQL Conversion→ Databricks→ Delta Lake→ Airflow Orchestration→ Validated Output
CASE STUDY 02 — LEGACY PLATFORM MODERNIZATION

Legacy SSMS Data Platform Modernization to Databricks

Modernized legacy client reporting and data-delivery workflows from SQL Server/SSMS and VisualCron to Databricks — using Databricks Lakebridge CLI for initial code conversion, followed by manual remediation, validation, and workflow development, with final output files generated and stored in AWS S3.

DatabricksLakebridge CLISparkPySparkSQLDelta LakeSSMSArgo WorkflowsYAMLAWS S3VisualCronGit

Problem & Role

  • Legacy client reporting and data-delivery workflows ran on SQL Server/SSMS with VisualCron orchestration — brittle, hard to maintain, and disconnected from the modern Lakehouse stack.
  • As Data Engineer, I owned the SQL conversion and remediation, the orchestration migration to Argo Workflows, and validation of the modernized platform against the legacy system.

Engineering Work

  • Migrated legacy SSMS workloads to Databricks using Lakebridge CLI for initial code conversion, followed by manual remediation of unsupported syntax and logic.
  • Converted and optimized SQL views, stored procedures, and complex queries for Databricks compatibility.
  • Migrated VisualCron workflows to Argo Workflows, developing and maintaining YAML-based job orchestration.
  • Performed SSMS vs. Databricks data validation — row counts, schemas, columns, and business logic — to confirm parity before cutover.
  • Troubleshot SQL conversion, permissions, dependencies, catalog/schema, and workflow issues surfaced during migration.
  • Automated CSV/ZIP file generation, AWS S3 storage, and SFTP delivery for client data feeds.
  • Collaborated with internal and client teams to resolve legacy logic and migration dependencies.
SQL Server / SSMS→ Lakebridge CLI Conversion→ Manual Remediation→ Databricks / Delta Lake→ Argo Workflows→ CSV/ZIP → S3 → SFTP
